# UI Design — PaintingCMS

**Версия:** 1.0 · **Автор:** Frontend UI Designer · **Вход:** `docs/ux-design.md` (flows), `openspec/changes/painting-cms/specs/ru-accessibility-ux/spec.md`, `design.md` (D8)
**Назначение:** визуальный слой для 7 экранов, удовлетворяющий жёстким требованиям a11y (базовый шрифт ≥18px, цели ≥48px, WCAG AA, видимый фокус, плоская навигация, русские подтверждения).
**Стек реализации:** Tailwind v4 + shadcn/ui (API компонентов shadcn НЕ меняются — переопределяются токены CSS-переменными), React 19, mobile-first внутри Telegram.

> ⚠️ **Примечание о входных данных:** файл `docs/ux-design.md` на момент работы отсутствовал в репозитории. Потоки и экраны восстановлены из `proposal.md`, `design.md` (D8) и всех domain-спецификаций; итоговый список из 7 экранов совпадает с планом фронтенд-лида (см. `data/handoffs/team/lead/frontend-lead/plan.json`). Если в `ux-design.md` появятся расхождения — приоритет у этого документа.

## 0. Мир интерфейса (контракт направления)

> **ТЕЗИС:** «Стена мастерской» — спокойный, тёплый интерфейс как хорошо освещённая стена галереи: бумага вместо пикселей, чернила вместо серого, одна сильная акцентная краска для главных действий. Никакого визуального шума — только крупное, контрастное, предсказуемое.
>
> **СВОЙ МИР:** тёплая бумажная подложка `#F7F2EA`, чернильный текст `#211A12`, одна акцентная краска — жжёная сиена `#A63D1F` (только для главного действия и фокуса), спокойные семантические зелёный/красный/янтарный. Углы 12–16px, минимальные тени, плоские поверхности с тонкими тёплыми границами. Типографика: один системный шрифт без засечек + Lora (кириллица) для заголовков экранов.
>
> **СТОРИЯ:** пожилой художник с ослабленным зрением открывает приложение и без раздумий видит: что это (крупный заголовок), что можно сделать (одна большая кнопка внизу), где его картины (крупные карточки). Каждое опасное действие спрашивает по-русски и дважды.
>
> **ПЕРВЫЙ ЭКРАН:** «Мои картины» — заголовок 28px, под ним карточки картин 120px высотой (фото 96px + название 20px + цена 20px + место), внизу прижатая к нижней панели большая кнопка «+ Новая картина» 56px акцентного цвета. Пустой список — дружелюбный 🎨 и кнопка-призыв.
>
> **ФОРМА:** светлая тема (день/студия), стратегия цвета Restrained (нейтральные + один акцент), режим Operate.
>
> **ФИНИШ:** дизайн-спецификация передана frontend-engineer; проверка реализованного UI — через test-engineer (axe, критично/серьёзно = 0) и finish-review.

**Режим:** Operate (пользователь выполняет задачу — ведёт учёт картин). Побеждают сканируемость, стабильность, предсказуемость. Экспрессия живёт в деталях (бумага, сиена, крупная типографика), а не в декорации.

**Стратегия цвета:** **Restrained** — нейтральные (тёплая бумага + чернила) + один акцент. Это единственно верный выбор для Operate: редкость даёт акценту силу. Один акцент = «главное действие». Семантические цвета (успех/опасность/предупреждение) — отдельные роли, не украшение.

**Светлая тема — основная** (сцена использования: художник в студии/галерее, дневной свет, телефон в руках; пожилой пользователь, низкое зрение). Тёмная тема — вторичный набор токенов, композиционно собранный (не механическая инверсия), для Telegram dark mode.

## 1. Дизайн-токены

Все токены — CSS-переменные в `:root` / `.dark`, которые frontend-engineer мапит в Tailwind v4 (`@theme inline`) и shadcn/ui. Имена переменных сохраняют контракт shadcn (`--background`, `--primary`, …), чтобы компоненты работали as-is. Расширения — `--success-*`, `--warning-*`, `--info-*`, `--danger-bg` и т.п.

**Принципы применения цвета:**
- Акцент — **только** главное действие, выбранная вкладка, кольцо фокуса, активная миниатюра. Никаких декоративных сиеновых пятен.
- Вторичный текст — тёплый серо-коричневый `#5F574A`, **никогда** холодный серый.
- Информация не передаётся цветом: везде иконка + текст, у выбранного состояния — жирность/заливка/символ.
- Хрома снижается у краёв светлоты (бледные фоны — пастельные, не насыщенные) — палитра остаётся спокойной.

### 1.3 Типографика

Базовый размер — **18px** (жёсткое требование; минимальный размер ЛЮБОГО текста в приложении — 18px). Межстрочный интервал тела — **1.5–1.6**. Ниже минимума текста нет вообще.

| Роль | Размер | Вес | Межстрочный | Применение |
|---|---|---|---|---|
| Display (заголовок экрана) | 28px | 700 | 1.2 | «Мои картины», «Картина», «Новая картина» |
| H2 (секция) | 24px | 700 | 1.3 | «Места продажи», «Владелец», заголовок диалога |
| H3 (название карточки) | 20px | 700 | 1.4 | название картины в карточке |
| Body / base | **18px** | 400 | **1.6** | весь основной текст |
| Body strong (цена) | 20px | 600 | 1.4 | цена с символом валюты |
| Label формы | 18px | 600 | 1.4 | подписи полей, над полем |
| Кнопка | 18px | 600 | 1.2 | все кнопки (lg) |
| Meta (даты, счётчики) | 18px | 400 | 1.5 | «4 из 10», даты истории |
| Badge | 18px | 600 | 1.2 | «Офлайн» / «Онлайн» |

**Шрифты:**
- **Основной (body, кнопки, поля):** системный стек без засечек — `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`. Гарантированная кириллица на всех платформах Telegram, ноль загрузки, ноль FOUT.
- **Display (только заголовки экранов h1/h2):** самозагружаемый **Lora** (кириллический сабсет, вес 600) с фолбэком `Georgia, "Times New Roman", serif`. Даёт тёплую «художественную» ноту без ущерба читаемости. Если самозагрузка нежелательна (вес в Telegram) — допустим чистый системный serif-фолбэк, тело и иерархия не страдают.
- **Цифры цен:** `font-variant-numeric: tabular-nums` — цены в списке выровнены по цифрам (важно для сравнения).
- Никакого `letter-spacing` меньше −0.01em; у заголовков 0–0.01em. Не использовать все капс для русского текста (русская капись хуже читается, чем латинская) — только обычный регистр.
- Мера строки: контейнер контента `max-width: 672px` (max-w-2xl) → 45–75ch при 18px. Поддерживать зум до 200% без горизонтального скролла.

### 1.4 Сетка, отступы, радиусы, тени

**Спайсинг (4-юнитная база):**

| Токен | Значение | Использование |
|---|---|---|
| `space-1` | 4px | микро-зазоры иконка-текст |
| `space-2` | 8px | между лейблом и полем, между иконкой и текстом в кнопке |
| `space-3` | 12px | внутренние отступы компактных элементов |
| `space-4` | 16px | внутренние отступы карточек, поля кнопок |
| `space-5` | 20px | горизонтальный паддинг экрана (mobile) |
| `space-6` | 24px | отступы между секциями, паддинг диалога |
| `space-7` | 32px | крупные разделы, верх экрана |
| `space-8` | 40px | над заголовком экрана, под пустыми состояниями |
| `space-9` | 48px | ритмические паузы (пустые состояния) |
| `space-10` | 64px | только нижняя граница последнего контента |

**Правила ритма:** больше пространства НАД заголовком, чем ПОД ним. Связанное — близко (проксимити прежде контейнеров). Один документированный масштаб, никаких одноразовых значений.

**Радиусы:**
- Карточки: 16px. Кнопки/поля/select/textarea: 12px (`--radius`). Диалог: 16px. Badge: пилюля (24px) — только для малых элементов. Миниатюры фото: 12px.
- Никаких «пилюльных» кнопок-таблеток для крупных действий — 12px достаточно, сохраняет спокойствие.

**Тени (минимальные, по правилу «elevation declared once»):**
- Карточки в списке: **только граница** 1px `--border-subtle` на белой заливке (плоская стена, никаких теней).
- Плавающие элементы (нижняя панель действий, диалог): одна мягкая тень `0 4px 16px rgba(33,26,18,0.14)` — офсет + размытие, без жёстких offset-теней.
- Нажатие (active): лёгкое затемнение заливки, БЕЗ «прыжка»/трансформации (никакой анимации).

**Сетка экрана (mobile-first):**
- Горизонтальный паддинг экрана 20px (`space-5`), с учётом `env(safe-area-inset-*)`.
- Одна колонка на телефоне. Desktop: контент `max-w-2xl` по центру, паддинг 24px.
- Никакого горизонтального скролла ни при каком размере и зум-уровне ≤200%.

## 2. Визуальная спецификация компонентов

Все компоненты — стандартные shadcn/ui (API не меняется), с токен-оверрайдами. Ключевое глобальное правило: **каждая интерактивная цель ≥48×48px**, кнопки по умолчанию `size="lg"`.

### 2.1 Button

| Свойство | Primary (по умолчанию) | Secondary (outline) | Destructive | Ghost (редко) |
|---|---|---|---|---|
| Заливка | `--primary` | `#FFFFFF` | `--destructive` | прозрачная |
| Граница | нет | 2px `--border` | нет | нет |
| Текст | `--primary-foreground` (белый) | `--foreground` (чернила) | `--destructive-foreground` (белый) | `--foreground` |
| Hover | `#8C2F12` | фон `#F1E6D6` | `#8C1D18` | фон `--muted` |
| Active | ещё темнее | фон `#E9E1D3` | ещё темнее | фон `#E9E1D3` |
| Focus | кольцо 3px `--ring` + офсет 2px | то же | то же | то же |
| Disabled | `--disabled-bg` + `--disabled-fg` (текст читаем 4.6:1) | то же | то же | то же |
| Размеры | `lg` = высота **52px**, паддинг 16×20px, radius 12px, текст 18px/600 | — | — | — |
| Минимум | **52px высота** (≥48 ✓), миниатюрные кнопки-иконки — 48×48px | — | — | — |

**Русские подписи (типизированные строки):** «Сохранить», «Отмена», «Удалить», «Редактировать», «Добавить», «Добавить картину», «Добавить место», «Выбрать», «Повторить», «Передать владельцу», «Открыть заново», «Назад».
- Кнопка с иконкой: иконка 22px слева + текст; иконка не заменяет текст (исключение — только 48×48 иконка-кнопка с `aria-label`).
- **Формат загрузки:** текст меняется на «Сохраняем…» (или «Удаляем…») + лёгкий спиннер 22px; кнопка disabled; спиннер — плавное вращение 1.2s linear, уважает `prefers-reduced-motion` (статичная точка). Никаких вспышек.
- Кнопка в нижней панели: **полная ширина**, 56px высота — самая большая цель на экране.

### 2.2 Card — карточка картины (список)

Структура (горизонтальная строка, высота ≥120px, вся карточка = одна ссылка/tap-цель):

```
┌──────────────────────────────────────────────┐
│ [фото 96×96]  Название картины       20px/700│
│   rounded12   Цена 12 500 ₽           20px/600│
│               📍 Офлайн · Галерея «Солнце»  18px │
└──────────────────────────────────────────────┘
```

- Фото: 96×96px, `object-cover`, radius 12px, слева; нет фото → плейсхолдер-блок `--muted` с иконкой 🖼 (архитектурно — серый блок + контур).
- Название: 20px/700, `--foreground`; цена: 20px/600 `--foreground` (tabular-nums) + символ валюты; место: 18px `--muted-foreground` + иконка места + badge.
- Заливка `--card` (белая), граница 1px `--border-subtle`. Hover (desktop): граница → `--border`; Active: фон `#FAF6EF`.
- Focus: кольцо 3px `--ring` + офсет 2px по всей карточке (карточка — `<a>`/`Link`).
- Список: одна колонка, gap 16px. Новые сверху.

### 2.3 Input / Select / Textarea — крупные, с подписью СВЕРХУ

- **Подпись:** 18px/600 `--foreground`, над полем, зазор 8px. Подпись никогда не исчезает (не placeholder-as-label — это барьер для пожилых).
- **Поле:** белая заливка, граница **2px** `--border` (5.4:1 — видна при слабом зрении), radius 12px, высота **56px**, текст 18px (ввод) / 20px (цена), паддинг 16px, внутренний зазор 8px.
- **Плейсхолдер:** 18px `--muted-foreground` (6.4:1 — читаем как текст).
- **Focus:** граница → `--ring` 2px + внешнее кольцо 3px `--ring` офсет 2px. Двойной сигнал: рамка + кольцо.
- **Hover (desktop):** граница темнее `#4F483C`.
- **Disabled:** `--disabled-bg` + `--disabled-fg`.
- **Ошибка:** граница 2px `--destructive`, под полем сообщение 18px `--destructive` с иконкой ⚠ (не цветом единым: иконка + текст); фон поля остаётся белым (не розовым — спокойствие); при фокусе на ошибочном поле — кольцо `--destructive`.
- **Textarea:** как поле, `min-height: 120px`, resize вертикальный, для «Адрес»/описаний.
- **Select (shadcn Select):** триггер как Input (56px), выпадающий список: белая панель, пункты высотой 56px, текст 18px, выбранный пункт — `--accent`-заливка + галочка ✓, hover — `--muted`. Фокус на пунктах — кольцо.
- **Числовое поле цены:** `inputMode="numeric"`, слева символ валюты (₽/$/€) 20px `--foreground`, цифры tabular-nums. Справа — «₽ 12 500» при вводе с пробелами-разделителями (локализация ru-RU — дело i18n-инженера, визуально: tabular-nums).

### 2.4 Dialog / AlertDialog — русские подтверждения

- **Оверлей:** `--overlay` (тёплый тёмный 55%). Без blur-эффектов (производительность и спокойствие).
- **Панель:** `--card`, radius 16px, паддинг 24px, `max-width: 400px`, по центру, тень `0 4px 16px rgba(33,26,18,0.14)`. Вход — лёгкое появление (fade 150ms, respect reduced-motion); БЕЗ scale-анимаций и bounce.
- **Заголовок:** 24px/700 (`--foreground`); **описание:** 18px/1.6 (`--foreground` или `--muted-foreground` для деталей).
- **Кнопки:** две, 52px, ряд. **Отмена = Secondary outline слева; подтверждение справа**: «Удалить» = Destructive (`--destructive` + белый текст) для удаления; «Передать владельцу» = Destructive для передачи прав (это необратимо для текущего владельца). Начальный фокус — на «Отмена» (безопасность), Tab переключает, Esc закрывает, фокус-ловушка внутри панели, кольцо фокуса на панели при открытии.
- **Иконка опасности:** в AlertDialog-удаления — круг 56px `--danger-bg` с иконкой 🗑 (или ⚠) 28px `--destructive`, слева от заголовка или над ним по центру. Иконка + текст + красная кнопка — тройной сигнал, не цвет один.
- **Примеры текста (диалоги):**
  - Удалить картину: «Удалить картину?» / «Картина и все её фотографии будут удалены навсегда. Это действие нельзя отменить.» / «Отмена» · «Удалить»
  - Удалить место (используется): «Удалить место?» / «Это место используется картинами: „Закат над рекой“, „Букет“. Сначала назначьте этим картинам другое место.» / «Понятно» (одна кнопка)
  - Передать владельцу: «Передать владельцу @username?» / «Вы больше не сможете открывать приложение. @username станет владельцем при следующем открытии.» / «Отмена» · «Передать владельцу»

### 2.5 Tabs / RadioGroup — переключатель валюты ₽/$/€ и вид места

**Сегмент-контрол (3 равные кнопки в ряд, высота 56px):**

```
┌────────────┬────────────┬────────────┐
│ ₽ RUB      │ $ USD      │ € EUR      │  ← 56px
└────────────┴────────────┴────────────┘
```

- Невыбранные: белая заливка, 2px `--border`, чернильный текст 18px/600.
- Выбранная: `--primary` заливка, белый текст 18px/700 + галочка ✓ (символ слева от кода) — **сигнал: заливка + цвет + жирность + галочка**, не цвет один.

- Тот же паттерн — **RadioGroup вида места** в форме локации, но крупнее (2 карточки по 64px): иконка 📍/🌐 + текст «Офлайн — адрес» / «Онлайн — сайт» + ✓ у выбранной, граница выбранной 3px `--primary` (не только цвет: ✓ + заливка + жирность).

### 2.6 Галерея фото + загрузчик

**Галерея (деталь картины):**
- Главное фото: **полная ширина** контейнера, aspect 4:3, radius 16px, `object-cover`. Без свайпа-анимаций (простой тап по миниатюре).
- Лента миниатюр: горизонтальный скролл, 76×76px, radius 12px, gap 8px; **выбранная** — рамка 3px `--primary` (не цвет: рамка + порядок + счётчик).
- Счётчик: «3 из 7» 18px `--muted-foreground` под лентой.
- Loading фото: блок 4:3 `--muted` с текстом «Загрузка…» 18px `--muted-foreground` (без скелетон-шиммеров и пульсаций); по загрузке — fade-in 150ms (respect reduced-motion).
- Нет фото: плейсхолдер-блок с 🖼 и «Нет фотографий» 18px `--muted-foreground`.

**Загрузчик (форма):**
- Сетка миниатюр 3 в ряд (на 360px+: 96×96px), gap 12px.
- Каждая миниатюра: 96×96px, radius 12px; кнопка удаления — **48×48px** в верхнем правом углу (белый круг с ✕ 20px чернильного цвета, поверх полупрозрачной тёмной подложки при фокусе/наведении; `aria-label` «Удалить фото»). Удаление по одному фото — **без диалога** (обратимо до сохранения) — просто исчезает.
- Плитка «Добавить фото»: 96×96px, пунктирная граница 2px `--primary`, иконка ＋ 28px `--primary`, подпись 18px `--primary-foreground`-не-нужна; `aria-label` «Добавить фото». Плитка — tap-цель ≥48px. При достижении 10 фото плитка скрыта.
- Подпись под сеткой: «Фотографии: 4 из 10» 18px `--muted-foreground`; ошибка: «Файл слишком большой. Максимум 10 МБ.» 18px `--destructive` + ⚠.
- Нативный файловый пикер `multiple accept="image/*"` — без кастомного drag&drop (сложность и риск для пожилых; нативный пикер — привычный).

### 2.7 Форма места (офлайн/онлайн)

### 2.9 Toast (уведомления)

- На экранах формы нижняя навигация (tab bar) СКРЫТА — вся панель принадлежит задаче.

**Состояния:**
- *Loading:* плейсхолдеры; *Error:* ⚠ + «Повторить».
- *Пользователь не найден (422):* inline-ошибка под полем «Пользователь не найден. Он должен сначала открыть приложение.»
- *Подтверждение:* AlertDialog (2.4) → «Передать владельцу @username?» / «Вы больше не сможете открывать приложение…» / «Отмена» · «Передать владельцу».
- *Успех передачи:* toast «Права переданы» + экран сменяется на «Сессия истекла»-подобный («Права переданы. Новый владелец вступит в права при следующем открытии.»), текущий владелец больше не видит данные.
- *Ошибка:* toast «Не удалось передать права. Попробуйте ещё раз.»

## 4. A11y-визуальные правила (контракт, видимый слой)

Эти правила — визуальное закрепление требований `ru-accessibility-ux`. Frontend-инженер реализует их буквально; test-engineer проверяет axe (critical/serious = 0) + визуальные сценарии.

1. **Фокус виден всегда и однозначно.** Кольцо 3px `--ring` + офсет 2px на всех интерактивных элементах (кнопки, поля, select, ссылки-карточки, вкладки, миниатюры, иконка-кнопки). `:focus-visible` для мыши (без колец на клик), но клавиатурный фокус — всегда. В тёмной теме — кольцо светлой сиены `#D65A2B`. Фокус не должен перекрываться нижней панелью (офсет учитывает).
2. **Контраст интерактивных состояний.** Текст ≥4.5:1 на всех состояниях (включая hover/active/selected); границы и иконки ≥3:1; фокус-кольцо ≥3:1. Проверенные пары — в таблице 1.1/1.2. Ни одно состояние не «падает» ниже нормы.
3. **Никакой информации цветом.** Выбранная вкладка: жирность + заливка + позиция; badge: иконка + слово; ошибка: ⚠ + текст; валюта: символ + код; вид места: иконка + слово + ✓. Цвет — усилитель, никогда не единственный носитель.
4. **Disabled остаётся читаемым.** Текст `#4F483C` на `#E9E1D3` = 4.6:1 — пользователь видит, ЧТО недоступно (не серое пятно). В тёмной теме 4.5:1.
5. **Цели ≥48×48px** (реально: кнопки 52–56, поля 56, вкладки 64, иконка-кнопки 48, карточки целиком). Миниатюры удаления фото 48×48. Кнопка в нижней панели 56px полной ширины.
6. **Типографика ≥18px везде.** Метаданные, badge, плейсхолдеры, toast — 18px минимум. Мера 45–75ch, межстрочный 1.5–1.6. Зум 200% без потери контента и без горизонтального скролла.
7. **Движение — только функциональное и единственное.** Один авторский момент: fade-in фото/toast (150–200ms). Спиннер загрузки — плавный, 1.2s linear. `prefers-reduced-motion: reduce` → никакой анимации (мгновенное появление). Запрещены: вспышки, мигание, parallax, skeleton-шиммеры, пульсации, авто-карусели, bounce-входы диалогов. (Не нанимать animations-engineer.)
8. **Порядок фокуса = визуальный порядок.** Чтение и таб-порядок идут сверху вниз по зонам экрана. В диалоге — ловушка фокуса, начальный фокус на «Отмена».
9. **Безопасные зоны Telegram.** Нижняя панель и tab bar учитывают `env(safe-area-inset-bottom)`; шапка — `env(safe-area-inset-top)`.
10. **Тёмная тема — не инверсия.** Отдельные значения ролей (1.2), особенно акцент с чернильным текстом.

## 5. Правила для frontend-инженера (handoff)

- Мапить токены 1.1/1.2 в Tailwind v4 (`@theme inline`) и shadcn CSS-переменные — API компонентов shadcn не менять.
- Все строки — из `src/lib/strings.ts` (типизированные русские строки); ни одного английского видимого слова.
- Базовый размер шрифта `html` = 18px (`font-size: 18px`), всё в `rem`.
- Компоненты: shadcn `Button size="lg"` по умолчанию, `Input/Select/Textarea` с токенами, `AlertDialog` для подтверждений, `Tabs`/`RadioGroup` для сегментов, `Card` для списка, `Sonner` для toast.
- Спиннеры — `<Loader2>` с классом анимации, уважающим `prefers-reduced-motion`.
- Карточки списка — одна ссылка (не вложенные кнопки); миниатюры удаления — кнопка с `aria-label`.
- Все иконки — из одного набора (lucide-react, 22–28px, stroke 2) + эмодзи ТОЛЬКО в пустых состояниях и бренд-марке (декоративные, `aria-hidden`), НЕ в интерфейсной иконографии.
