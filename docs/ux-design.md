## 0. The Design Brief (from the Director, verbatim)

> DESIGN: mobile first. A11Y: the user is a Boomer and is not good at navigating complex UIs, everything should be super accessible and easy to understand and navigate, the user also has a bad vision, so the font size shouldn't be too small. LANG: the entire app must be 100% be in the Russian language.

### Assumptions (no interview round was possible in this microtask — the Director's words are the interview answers)

- **Persona.** Один человек — художник (паинтер) 60+, носитель русского языка, плохое зрение, низкая уверенность с цифровыми интерфейсами. Пользуется приложением в Telegram на телефоне. Одна задача за раз. Ошибки пугают → их нужно предотвращать и мягко объяснять.
- **One owner, one app.** Единственный владелец ведёт каталог своих картин: добавляет, смотрит, редактирует, удаляет, ведёт места продажи, может передать приложение другому человеку.
- **Claim-on-first-open is invisible.** Первый открывший приложение автоматически становится владельцем — без диалогов, без страха, без технических объяснений.
- **Desktop exists but is not a design target.** Phone-in-Telegram is the surface; desktop must merely remain usable (spec).

### Design principles (what "super accessible and easy" means here)

1. **Flat and linear.** Каждый экран достижим с главного списка за 1 тап, или через один явный путь «Назад». Никаких вкладок, bottom-nav, гамбургеров, скрытых меню.
2. **One job per screen.** На каждом экране одна главная кнопка. Второстепенное — мелким и ниже.
3. **Big everything.** Крупный текст (≥18px), крупные кнопки (≥48×48px, главные — выше), крупные поля.
4. **No jargon, no English.** Короткие русские предложения, бытовые слова («фото», «цена», «место»), никакой технической лексики, никаких непереведённых строк.
5. **Say what will happen before it happens.** Каждое разрушительное действие подтверждается понятным русским диалогом.
6. **Never lose the user's data.** При любой ошибке введённое сохраняется; ошибка объясняется по-русски и даёт следующий шаг.
7. **Status is always visible.** Загрузка, успех, ошибка — всегда есть явный отклик на действие.

## 1. Information Architecture (flat map)

```
                    ┌────────────────────────────────────────────┐
                    │  Список картин  (home, after gate)          │
                    │  · big CTA  «+ Добавить картину»            │
                    │  · cards → Картина                          │
                    │  · footer: Места продажи · Владелец         │
                    └───────┬───────────┬───────────┬────────────┘
          tap card          │           │           │ footer links
              ▼             ▼           ▼           ▼
        ┌──────────┐  ┌──────────────┐  ┌──────────────┐  ┌────────────┐
        │ Картина  │  │ Новая картина │  │ Места продажи │  │ Владелец   │
        │ (detail) │  │ / Редактиров. │  │ (bank CRUD)  │  │ (transfer) │
        └────┬─────┘  └──────────────┘  └──────┬───────┘  └────────────┘
   Изменить │  Удалить                          │ tap row / +
        ▼   ▼                                  ▼
   (form — 1 tap)                        add/edit location
```

**Depth rules (spec: flat navigation, ≤1–2 taps):**
- Every screen reachable from home in **1 tap** (card → detail; CTA → create; footer → locations/owner).
- Every edit reachable in **2 taps** max (detail → «Изменить» → form; locations → row → edit).
- **No tabs, no bottom navigation, no hamburger, no nested menus.** Back is always the Telegram back button + an in-app text button «Назад».
- External exits (map/URL in Telegram browser) are the only "leave" — always via an explicit tappable link.

**The gate is NOT a screen** (frontend-lead decision): bootstrap → SDK init → POST initData → owner ? «Список картин» : «Доступ запрещён». Claim happens in the backend on first auth; the UI shows the list immediately with a one-time welcome banner (never a dialog).

## 3. User Flows (step-by-step, happy + error)

### Flow A — First open → ownership claim

**Happy path**
1. Владелец открывает приложение из Telegram (menu button / ссылка).
2. Gate: SDK init → initData захвачен один раз → POST auth.
3. Backend записывает первого пользователя и делает его владельцем (транзакция, race-safe). Ответ: owner = true.
4. Роутер → «Список картин» (пустой). **Никаких диалогов, никаких страшных подтверждений.**
5. Одноразовый welcome-баннер поверх списка: «Добро пожаловать! Теперь это ваше приложение.» + [Понятно] (баннер, НЕ диалог; исчезает навсегда после закрытия).
6. Пустое состояние: «У вас пока нет картин» + «+ Добавить первую картину».

**Error paths**
- 401 (невалидный/протухший initData) → «Сессия истекла» + [Открыть заново].
- Сеть недоступна на auth → баннер «Не удалось подключиться. Проверьте интернет.» + [Повторить] (data сохраняется в state).
- 403 (уже есть владелец, открыл не владелец) → «Доступ запрещён» — **без единого запроса данных**.

### Flow B — Create painting

**Happy path**
1. Список → тап «+ Добавить картину» (1 тап).
2. «Новая картина»: тап «Название» → ввод (крупная клавиатура).
3. Тап «+ Добавить фото» → выбор нескольких фото из устройства → крупные превью; «×» убирает фото.
4. Тап «Цена» → ввод числа (запятая допустима) → тап валюты «₽ Рубли» (по умолчанию RUB).
5. Место: тап **«Выбрать место»** → список банка → тап строки → возврат в форму, место показано. **Или** тап **«Добавить новое место»** → вид «Офлайн (адрес)»/«Онлайн (сайт)» → ввод адреса/URL → «Готово» → место показано.
6. Тап «Сохранить» → toast «Картина сохранена» → переход на «Картина».

**Error paths**
- Без названия → инлайн под полем: «Введите название». Сохранение не происходит.
- Без места → инлайн: «Выберите место продажи».
- Отрицательная цена → инлайн: «Цена не может быть отрицательной».
- Невалидный URL при инлайн-добавлении → инлайн в мини-форме: «Введите адрес сайта, например https://art.ru».
- Фото не загрузилось → под фото: «Не удалось загрузить фото. Попробуйте ещё раз.»
- Сервер/сеть на «Сохранить» → баннер + [Повторить]; **все введённые данные сохраняются** (никакой потери при ошибке).

### Flow C — Edit painting

**Happy path**
1. «Картина» → тап «Изменить» (1 тап).
2. «Редактирование картины» — все поля предзаполнены.
3. Изменения → «Сохранить» → toast «Изменения сохранены» → возврат на обновлённую «Картину».

**Error paths** — те же, что в Flow B (инлайн-валидация, данные не теряются). Смена места на занятое другими картинами не ограничена — место в банке переиспользуемо.

### Flow D — Delete painting

**Happy path**
1. «Картина» → «Удалить».
2. AlertDialog: «Удалить картину «{название}»?» / «Это действие нельзя отменить.» → [Удалить] [Отмена].
3. «Удалить» → запись и фото удаляются → возврат на список → toast «Картина удалена».
4. «Отмена» → ничего не меняется.

**Error path** — удаление не удалось → toast «Не удалось удалить. Попробуйте ещё раз.» (диалог закрыт; картина на месте).

### Flow E — Locations management

**Add happy path**
1. «Места продажи» → «+ Добавить место».
2. Вид: «Офлайн (адрес)» / «Онлайн (сайт)» (два больших тумблера).
3. «Адрес» или «Сайт» → ввод → «Сохранить» → toast «Место добавлено», строка в списке с бейджем «Офлайн»/«Онлайн».

**Add error paths** — пустой адрес: «Введите адрес»; невалидный URL: «Введите адрес сайта, например https://art.ru» (инлайн).

**Edit** — тап строки → предзаполненная форма → «Сохранить» → toast «Место изменено»; обновляется везде, где используется.

**Delete unused** — «Удалить» → диалог «Удалить место?» / «Это действие нельзя отменить.» → [Удалить] → toast «Место удалено».

**Delete in use (spec: warn + block)** — «Удалить» → диалог: «Это место используют картины: «{названия}». Сначала замените место у этих картин.» → [Понятно]. Удаление заблокировано; пользователь идёт в карточки картин и меняет место, затем повторяет удаление.

### Flow F — Ownership transfer

**Happy path**
1. Список → футер «Передать владельцу» (1 тап).
2. «Владелец»: карточка текущего владельца + объяснение + поле «Имя пользователя в Telegram».
3. Ввод «@username» (с @ или без) → тап «Передать».
4. AlertDialog: «Передать права владельца пользователю @username?» / «После этого вы потеряете доступ к приложению.» → [Передать] [Отмена].
5. [Передать] → запрос → успех → спокойный полноэкранный экран «Права переданы пользователю @username» (без действий; приложение прекращает запросы — бывший владелец сразу без доступа, но БЕЗ показа ошибки).
6. Новый владелец открывает приложение → становится владельцем → видит полный список. Бывший владелец при следующем открытии видит «Доступ запрещён».

**Error paths**
- Пустое поле → инлайн «Введите имя пользователя».
- 422 (пользователь никогда не открывал приложение) → инлайн/баннер: «Этот пользователь ещё не открывал приложение. Попросите его открыть приложение, а затем попробуйте ещё раз.» Поле сохраняет ввод.
- [Отмена] в конфирме → ничего не меняется, владелец остаётся.
- Сеть → баннер + [Повторить].

### Flow G — Denied access

1. Не-владелец открывает приложение → gate: 403 → «Доступ запрещён».
2. Объяснение по-русски; никаких действий; Telegram back закрывает.

### Flow H — Expired session

1. Любой ответ 401 → приложение переключается на «Сессия истекла».
2. «Открыть заново» → новый initData (re-init SDK) → повтор gate → список (если владелец) или «Доступ запрещён».

## 4. Accessibility Design Rules — THE CONTRACT for the frontend engineer

These are requirements, not suggestions. The Test Engineer asserts them in E2E (axe critical/serious = 0, keyboard CRUD, tap targets ≥48px, large-text no-overflow).

### 4.1 Typography
- **Base font ≥18px** для всего body. Шкала: 18 / 20 (subtitle/body-strong) / 24 (h3, счётчики) / 28 (h2, заголовки экранов поменьше) / 32 (h1, заголовки экранов). **line-height ≥1.5** для текста, ≥1.3 для заголовков.
- **rem-единицы** (не px) — размер следует за настройками ОС/Telegram. Шкала токенами, не «захардкоженными» значениями.
- **Fluid type + overflow-wrap:anywhere** — при крупном тексте (html 24px+, OS font scaling) ничего не ломается: нет фиксированных высот, нет горизонтального скролла (E2E: 390×844 и 390×500).
- Минимум текста: одно предложение на мысль; короткие слова.

### 4.2 Touch targets
- **Все интерактивные элементы ≥48×48px** (spec). Первичные CTA — полная ширина, высота ≥56px.
- Расстояние между соседними интерактивными целями ≥8px; между конфликтующими действиями («Удалить» / «Изменить») ≥16px.
- Метки и поля: высота поля ≥52px, метка над полем, крупная, всегда видимая (не только placeholder).

### 4.3 Color & contrast
- **Пол (contract):** обычный текст ≥4.5:1 (WCAG AA), крупный текст ≥3:1; **целевой уровень для body — 7:1 (AAA)** — дешёвый выигрыш для плохого зрения.
- Не-текстовые элементы (границы, фокус-кольца, бейджи) ≥3:1 к фону.
- **Направление палитры (для UI-дизайнера):** высокая контрастность, спокойная, тёплая, без мерцания. Тёмный текст (#1a1a1a) на тёплом светлом фоне (#faf7f2); первичное действие — тёмное/сильное; опасное — #c62828 на светлом (≥4.5:1). Не использовать жёлтый/светло-зелёный для важного текста.
- **Никакой статус только цветом:** бейджи «Онлайн»/«Офлайн» — текстовые + иконка (цвет — дополнение).
- Тёмная тема (telegram themeParams dark): те же полы контраста; не полагаться на дефолтные цвета Telegram без проверки.

### 4.4 Focus & keyboard
- **Фокус видим всегда:** кольцо ≥3px, контраст ≥3:1 к окружению; фокус не скрывается при mouse-использовании (только :focus-visible не снимается).
- Полная клавиатурная операция (desktop): Tab — линейный порядок = визуальный порядок; Enter/Space активируют; Esc закрывает диалог; в диалоге focus-trap; после закрытия фокус возвращается к триггеру.
- Семантические элементы: `<button>` для кнопок, `<a>` для ссылок, формы с `<label for>`.

### 4.5 Motion
- **prefers-reduced-motion: reduce → все анимации/переходы отключены.** Даже без него: только CSS-переходы (press-состояния, fade диалога), никаких авто-анимаций, параллакса, пульсаций.
- **Haptics: off by default** (см. §5) — никакой вибрации-сюрприза.

### 4.6 Language & copy
- Короткие русские предложения, бытовые слова: «фото», «цена», «место», «картина»; без жаргона и англицизмов («сайт» — ок; «URL» — только в примере ввода).
- Ошибки объясняют действие, а не технику: «Не удалось загрузить. Проверьте интернет.» — никогда «Error 500», стектрейсов, английских исключений.
- Числа/цены — ru-RU locale: «12 500 ₽», «0,50 ₽».

### 4.7 Components
- **Icon+label всегда:** ни одна кнопка не бывает только иконкой; иконки декоративны (aria-hidden).
- **Alt-текст:** фото картины — «Фото картины «{название}»»; декоративные иконки скрыты.
- **Toasts/баннеры — aria-live="polite"** (успех/ошибка озвучиваются скринридером).
- **Диалоги подтверждения:** AlertDialog, центрирован, кнопки **вертикально** на мобильном (меньше промахов): [Удалить]/[Передать] (опасная, красная) над [Отмена] (нейтральная); обе ≥48px; фокус на «Отмена» по умолчанию (защита от случайного разрушения).
- Заголовки: ровно один h1 на экран; иерархия h1→h2; landmarks `<header>/<main>`.

### 4.8 Forms
- Метка над полем, ≥18px, всегда видна; placeholder — русский, вспомогательный (никогда единственная метка).
- Ошибка — под полем, красный текст ≥4.5:1, связана aria-describedby, озвучивается; поле подсвечено, но НЕ только цветом (иконка/текст).
- Первичная кнопка формы — внизу, полная ширина, в зоне большого пальца.

## 5. Telegram Mini App UX Notes

- **Viewport:** `viewport-fit=cover`; после init — `viewport.expand()`; избегать фиксированных нижних панелей (кроме safe-area-aware); `scroll-padding-bottom` при открытой клавиатуре; проверить 390×844 и 390×500 (клавиатура).
- **Safe areas:** `env(safe-area-inset-bottom/top)` — отступ под home-indicator; контент не прячется под системные элементы Telegram.
- **Back button:** синхронизировать системную BackButton Telegram (SDK) с роутером; на корневом экране — закрытие приложения. Дополнительно — видимый in-app «Назад» (текстом) для наглядности.
- **Large-text compatibility:** тема должна выдерживать крупные системные шрифты без обрезки (rem, overflow-wrap, нет фиксированных высот).
- **Haptics: off** (WebApp hapticFeedback НЕ использовать по умолчанию — вестибулярный риск для пользователя; CSS press-состояние достаточно).
- **Telegram MainButton: не использовать** для первичного CTA — крупная кнопка внутри экрана проще, предсказуемее, без конфликта с клавиатурой/панелями.
- **Первая загрузка:** цель <3s (лимит от frontend-lead); скелетон вместо спиннера на списке; код-сплит формы.
- **Внешние переходы:** «Открыть сайт» — только явная ссылка (Telegram browser); назад возвращает в приложение.
